# Seal the day from the log file

A day is sealed when `05 时间日志/YYYY-MM/DD｜*.md` exists and is not the to-summarize stub. That file is the answer.

A runner's receipt is not. Health pages and run ledgers only prove whether *that* writer fired; a seal written by hand, by another host, or by a different mount never appears in them.

So before you report a gap or re-distill a day, list the month's directory first. If a real note is already there, fill only the missing part — or re-distill when the host names a model for it, and say in the page that it supersedes the earlier draft. Never report an existing note as a missing day.

## Evidence

Backfilling two days: the first already held a draft, so it was re-distilled on request and marked as superseding; the second was a to-summarize stub, so it was distilled whole. Reading the runner's ledger alone would have reported the first day as never sealed.

## How this page became formal

It was written as a `provisional` draft on the day the five gates passed. On the next backfill the host was asked, adopted it, and that task was accepted — which is the only path to `active`. The draft it came from is kept and marked as superseded.
